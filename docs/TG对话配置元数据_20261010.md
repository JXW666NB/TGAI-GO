# ★ .TG 对话配置元数据（让模型自带模板）

**日期**：2026-10-10
**目的**：让**模型文件自己**声明"怎么跟它对话"，而不是把格式硬编码在引擎里

---

## 一、为什么需要（用户需求）

```
问题：现在 V2.7 的九标记格式硬编码在引擎/Python 里
  ⇒ 接第三方模型（Llama/Qwen/自定义）要改代码
  ⇒ TGAI 以后改格式（V3/V4）也要改代码

目标：改成【改模型元数据】就能适配
  ⇒ 第三方模型打包时带上配置，TGAI GO 直接能用
```

---

## 二、段格式（TLV，向前兼容）

放在 `.TG` 文件**末尾**，用 header offset 124 的 `extension_off` 指向它。

```
[magic "TGCF" 4B][version u32][count u32]
count 个条目，每个：
   [type u32][len u32][data len B]

★ 读取方遇到不认识的 type 直接跳过 ⇒ 新版加字段不会让老引擎崩
```

### 条目类型

| type | 名称 | 内容 |
|---|---|---|
| 1 | `chat_template` | 模板字符串（占位符见下） |
| 2 | `stop_strings` | 停止串，`\x00` 分隔 |
| 3 | `turn_markers` | 轮次边界标记（生成到它即停），`\x00` 分隔 |
| 4 | `special_tokens` | 整段匹配的特殊标记，`\x00` 分隔 |
| 5 | `gen_defaults` | 采样默认值，`k=v` 用 `\x00` 分隔 |
| 6 | `system_prompt` | 默认系统提示 |
| 7 | `render_mode` | `markers` / `chatml` / `plain` |
| 8 | `template_turn` | 单轮历史模板（含 `{Q}`/`{A}`） |

### 模板占位符

| 占位符 | 含义 |
|---|---|
| `{SYS}` | 系统提示（无则整段省略） |
| `{HIST}` | 历史轮次（按 `template_turn` 反复展开） |
| `{Q}` | 当前问题 |
| `{A}` | 助手回答（只在 `template_turn` 里用） |
| `{TAIL}` | 末尾档位标记（`<回答>` / `<思考>`） |

## 三、★★ `extension_off` 的编码约定（踩坑记录）

### 问题

```
header offset 124 是 u32（最大 4 GB）
而 V2.7 的 .TG 是 5.64 GB
⇒ 绝对偏移【放不下】
```

### 约定（向后兼容 v1）

```
= 0                   无段（v1 老文件）
> 0 且 < 2^31         绝对偏移（老文件都是这种）
高位为 1（有符号负）   段在文件末尾：实际偏移 = file_size + signed(off)
                      例：段长 405 ⇒ off = 0xFFFFFE6B (= -405)
```

### 🔴 踩的坑：Windows 的 `ftell()` 是 32 位

```
C 侧一开始写:
    long fsz = ftell(f);              // ← Windows 上 long = 32 位！
    ext_off = fsz + s32;

5.64 GB 的文件 ⇒ ftell() 溢出返回 -1
⇒ ext_off = -1 + (-405) = -406
⇒ 判为负数 ⇒ 永远读不到配置

★ 实测症状（调试输出）:
    [dbg] raw_off=0xFFFFFE6B
    [dbg] ext_off=-406          ← 本该是 6058096640
    [chat-meta] (模型内无对话配置)

★ 修正：必须用 64 位版本
    #if defined(_WIN32)
    #  define TG_FSEEK64(f, off)  _fseeki64((f), (long long)(off), SEEK_SET)
    #  define TG_FTELL64(f)       _ftelli64(f)
    typedef long long tg_foff_t;
    #else
    #  define TG_FSEEK64(f, off)  fseeko((f), (off_t)(off), SEEK_SET)
    #  define TG_FTELL64(f)       ftello(f)
    #endif

★ 另一个坑：段读取缓冲区写死 4096 字节
    ⇒ 改为按【文件末尾 - 段起始】精确计算（上限 4 MB 防呆）
```

## 四、用法

### 给模型写配置

```bat
:: 查看现有配置
python tools\write_chat_meta.py <model.TG> --show

:: 写内置预设（v27 / chatml / plain）
python tools\write_chat_meta.py <model.TG> --preset v27
python tools\write_chat_meta.py <model.TG> --preset chatml

:: 清除配置
python tools\write_chat_meta.py <model.TG> --clear
```

### 引擎读取（自动）

```
启动时输出:
  [chat-meta] 模型自带对话配置: mode=markers stop=6 markers=5 special=9
              采样默认: temperature=0.6 top_k=40 top_p=0.9 repeat_penalty=1.05 min_tokens=4 max_tokens=256
  [meta] 采用模型内嵌采样默认: top_k=40 top_p=0.9 min_tokens=4
```

## 五、三档优先级（配置来源）

| 项 | 优先级（高 → 低） |
|---|---|
| **停止串** | `--stop` / `TGAI_STOP` → 模型元数据 → 引擎内置默认 |
| **采样默认值** | CLI 显式给值 → 模型元数据 → 引擎内置默认 |
| **min_tokens** | `--min-tokens` → 模型元数据 → 4 |
| **渲染模式** | 模型元数据 `render_mode` → 按 `arch_type` 猜 |

```
CLI 关掉元数据默认值：--no-meta-defaults
```

## 六、V2.7 预设的实际内容

```
render_mode    markers
chat_template  {SYS}{HIST}<用户>\n{Q}\n<TGAI>{TAIL}\n
template_turn  <用户>\n{Q}\n<TGAI><回答>\n{A}
special_tokens <用户> <TGAI> <思考> <回答> <系统> <记忆> <工具表> <TGH> <工具结果>
turn_markers   <用户> <TGAI> <系统> <记忆> <工具表>
stop_strings   <用户> <TGAI> <系统> <记忆> <工具表> <TGH>
gen_defaults   temperature=0.6 top_k=40 top_p=0.9 repeat_penalty=1.05
               min_tokens=4 max_tokens=256
```

**★ 为什么 `turn_markers` / `stop_strings` 不含 `<思考>`/`<回答>`**：
它们出现在回答**内部**（`<TGAI><思考>…</回答>`），当停止串会把回答拦腰截断。
