## 三、验证方法与结果

### 3.1 分词一致性（最关键）

```
工具: tools/verify_bpe_v27.py
方法: 用「V2.7 词表 + 老模型权重」的 .TG，对比引擎 tg_encode 与 HF tokenizer

结果:
  你好 / TGAI / 什么是TGAI / Hello world / 1+1是多少？
  def f(x): return x+1 / 我喜欢吃苹果和香蕉。
  <用户>\n你好\n<TGAI><回答>\n
  <TGAI><思考>\n嗯，让我想想。\n\n<回答>\n答案是 2。
  2026年10月9日
  <系统>你是TGAI<记忆>无<用户>你好<TGAI><回答>

  ⇒ 0/11 条不一致   🎉
修复前: 10/10 不一致（TGAI 被编成 4 个字节 token）
```

### 3.2 QB 路由偏置

```
工具: tools/verify_qb_bias.py
方法: ①原模型 ②注入 _qb_bias=0 ③注入 _qb_bias≠0

① vs ②  ✅ 完全一致    ⇒ 加载路径不破坏计算
① vs ③  ✅ 输出已改变  ⇒ 偏置真进了路由（差异 3/17 token）
```

### 3.3 采样器单元测试

```
① seed 可复现        ✅ 两次一致
② repeat_penalty     ✅ logit 5.00 → 2.50
③ frequency_penalty  ✅ 1次→4.50, 3次→3.50, 10次→0.00
④ DRY                ✅ 重复续写 token 5.00 → 3.00
⑤ min_p              ✅ 只出峰值 token
```

### 3.4 老模型零影响

```
_phone_v1q4.tg（无 merges / 无特殊标记）:
  decode 编码正常、前向正常、生成正常
  n_special=0 ⇒ 不匹配任何特殊标记 ⇒ 行为与改动前一致
```

## 四、遗留问题（下一步）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | **正则 `pre_tokenizer` 未完整复刻** | 极端情况（连续多空格、制表符、混合标点）可能不一致 | 按 `Isolated` 语义对齐 + 扩充边界测试集 |
| 2 | **vocab hash 表未做** | 每字符 O(vocab)=32779 次 `strcmp`，编码慢 | 加载时建开放寻址 hash 表 |
| 3 | 并行分发优化效果未定论 | 4→8 线程仍掉 29% | 在稳定环境复测；考虑 work-stealing |
| 4 | **MoE 专家权重 packing 未做** | 预取器失效（我实测"8 行点积"反而慢 10%）| 按 `[expert][row][k]` 连续打包 + 批量专家 GEMM |
| 5 | **BF16 未支持** | 模型原生 BF16，转换有精度损失 | 加 `TG_DTYPE_BF16=6`（方案见 §能力差距文档）|
| 6 | Q4_K / i8mm 未支持 | 移动端性能 | — |
| 7 | 嵌入式 MoE 未做 | ESP32 只能跑 dense 小模型 | 见 §能力差距文档 §九 |
