## 二、★ 找到的三个真正差距（已修）

### 2.1 prompt 末尾必须带换行

**来源**：官方 Jinja 模板 `experiment_ollama\jinja\_tgai_v27.jinja` 最后一行
```jinja
<TGAI><回答>
                    ← 末尾换行
```
**训练格式**：`<用户>\n{q}\n<TGAI><回答>\n{a}` ⇒ 答案前有换行

**实测**：加换行后 `\n` 的 logit 从 **9.2 降到 8.4**（更易被惩罚压低）

**修复**：`tgai_chat.py` L420
```python
p.append(f"<用户>\n{msg}\n<TGAI>{tail}\n")     # ★ 末尾 \n
```

### 2.2 ★ DRY 的 breaker 语义实现错误

**我的原实现**（L286-289）：
```python
seg = ''.join(texts[found:found+mlen])
if any(b in seg for b in brk):    # ← 匹配段含 \n 就整条跳过
    continue
```
**问题**：`DRY_BREAKERS` 含 `\n` ⇒ **恰好把 `\n` 复读的匹配全跳过了** —— 而它正是要压的目标！

**llama.cpp 的正确语义**（读 `llama-sampler.cpp` L3424-3461 确认）：
breaker 只用于**限制匹配长度上界 `rep_limit`**（遇到 breaker 就把上界截到它之前），
**不是"出现就跳过规则"**。

**修复**：改为先求 `rep_limit`，再限制 `mlen` 上界。

### 2.3 ★ 权威参数（从 `tuner\index.html` 的 PRESETS 读出）

```javascript
final: {temperature:0.3, top_k:60, top_p:0.9, min_p:0, seed:-1,
        repeat_penalty:1.25, repeat_last_n:512,          ← 我原用 64
        frequency_penalty:0.25, presence_penalty:0,
        dry_multiplier:1.25, dry_base:1.75,
        dry_allowed_length:3, dry_penalty_last_n:512,    ← 我原用 2 / 128
        n_predict:400}
dry50: {… dry_multiplier:5.0 …}   ← 面板标注「实测复读率 0% 的甜点」
```

**面板自己的修正记录**：
> frequency_penalty 1.2 → 0.25。旧值 1.2 是安全上限(0.4~0.6)的 3 倍，长对话必崩。
> 实测：rep 1.25 + freq 0.25 在 6 轮长上下文下连贯；freq 0.6 起不稳定。

**修复**：`tgai_chat.py` 默认值 10 处全部对齐权威值。

## 三、修复效果（端到端实测）

**修复前**（零惩罚 / 窗口 64 / dry 0.8 / 无尾换行）：
```
'\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n'      ← 纯换行复读，0 个汉字
```

**修复后**（权威参数 / dry 5.0 / 尾换行 / breaker 语义修正）：
```
注：
-称：

（，）：

注：。

注：
```
**⇒ 出汉字与标点了（`注/称/不/是/我/说/有问/这`），速度 12.2 tok/s**

**仍存问题**：约 120 token 后出现复读（`不，这，有问，我说：` × 5）

**原因分析**（DRY 公式）：
```
penalty = 5.0 × 1.75^(repeat_len - 3)
  repeat_len=3 → 5.0     （不够压 8.4 的 logit）
  repeat_len=4 → 8.75
  repeat_len=5 → 15.3    （才够）
```
**⇒ DRY 生效需要匹配长度 ≥ 5**。这既说明语义正确（`\n` 已被压住），
也说明**需要更强的早期压制**。
