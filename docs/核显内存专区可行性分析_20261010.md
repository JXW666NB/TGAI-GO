# ★ 核显"内存专区"可行性分析 + 我要修正的一个错误

**日期**：2026-10-10
**问题**：能不能给核显划一片专属内存，让 CPU 不抢？

---

## 一、先分清两件不同的事

| 类型 | 能否做到 | 是否解决"抢总线" |
|---|---|---|
| **① 硬件保留区**（BIOS UMA Frame Buffer）| ✅ 能 | ❌ **完全不解决** |
| **② 软件配额/优先级**（类 PCL 滑块）| ✅ 能 | ⚠️ 只能减少**软件层**竞争 |

### 为什么 ① 不解决根本问题

```
核显与 CPU 【共享同一个内存控制器 + 同一对物理内存条】

BIOS 的"专用显存"实际上是什么：
  · 在物理地址空间里划出一段【保留给 GPU 使用】的地址范围
  · 驱动程序只从这段里分配（而不是从共享区）
  · ★ 但那段内存物理上仍然是同一对 DDR4 内存条

⇒ 保留区 ≠ 更快的内存
   数据仍然要通过同一条 DDR4 通道、同一个内存控制器
⇒ 带宽完全不变（51.2 GB/s 理论）
```

**打比方**：把书架的一层划给你专用，不等于书架变宽了。
别人不来抢那一层，但书架还是那么宽。

### ② 软件配额能做什么

```
能做到：
  · 防止某个进程吃光内存导致核显分配失败
  · 给 GPU 相关操作更高优先级（Vulkan 队列优先级已支持）
  · 让 CPU 侧工作线程数减少，降低对内存控制器的压力

不能做到：
  · 增加物理带宽
```

## 二、★ 我必须纠正一个错误结论

### 我之前说的

```
"核显带宽实测 ~7 GB/s ⇒ 806 ms/token ⇒ 比 CPU 慢 9 倍"
```

### 重新核算（用引擎的真实数据）

```
引擎实测: 11.0 tok/s = 91 ms/token

V2.7 每 token 实际需要读取的权重:
  权重总量 5.64 GB（BF16）
  MoE 8 选 2 ⇒ 专家只读 2/8
  专家占权重 93.1%（实测）
  ⇒ 每 token 实读 ≈ 5.64 × (0.069 + 0.931 × 2/8) ≈ 1.70 GB

有效带宽 = 1.70 GB ÷ 91 ms = 18.7 GB/s

理论带宽 = 2 × 8 GB × 3200 MT/s ÷ 8 = 51.2 GB/s
⇒ 利用率 ≈ 36%
```

### 这意味着什么

| 我之前的判断 | 修正后的判断 |
|---|---|
| CPU 只用了 13.7% 带宽，有 7 倍空间 | **CPU 用了约 36%**，仍有空间但小得多 |
| GPU 常驻会比 CPU 慢 9 倍 | **这个结论不成立** —— 两者面对的是同一个带宽上限 |
| "CPU 带宽优化"是 P1 优先项 | 仍可做，但**收益预期要下调** |

**⚠️ 更重要的修正**：
```
核显与 CPU 共享同一条内存总线
⇒ 核显"跑得快"的唯一可能，是它的【每字节数据能算更多 FLOP】
   即：算力/带宽比更高

实测对比：
  CPU 单线程 AVX2:  2.8 GFLOP/s  ÷ 18.7 GB/s ≈ 0.15 FLOP/byte
  核显 seq=8:     164.1 GFLOP/s ÷ ? GB/s     ≈ 8.8 FLOP/byte（按同样带宽估）

⇒ 核显的算力/带宽比高 50 倍！
⇒ 但 decode（seq=1）时计算量太小（8.4 MFLOP/矩阵乘），
   算力优势完全浪费 —— 瓶颈退化成纯带宽
⇒ ★ 所以 GPU 只在 seq 大（prefill）时才有优势（这个结论仍然成立）
```

## 三、你真正能"分区"的东西（实测可用）

### 3.1 系统层（需重启进 BIOS）

```
本机当前: 核显专用显存 = 512 MB（WMI 报告）

BIOS 里通常叫:
  · "UMA Frame Buffer Size"       （AMD 笔记本常见）
  · "Dedicated Video Memory"
  · "iGPU Memory" / "Share Memory"

可选值通常: 32M / 64M / 128M / 256M / 512M / 1G / 2G / Auto

★ 对本机的影响:
  调大 ⇒ 核显有"专用"地址范围，但【带宽不变】
       且【减少系统可用内存】（你只有 16 GB！）
  调小 ⇒ 系统内存更多，核显仍可通过共享区使用（实测能到 7.25 GB）
⇒ 建议: 保持 512 MB 或设 Auto，不要调大
```

### 3.2 软件层（用户态，立刻可用）—— 类似 PCL 那个滑块

| 手段 | 效果 | 本机可行性 |
|---|---|---|
| **限制 CPU 工作线程数** | 降低内存控制器竞争 | ✅ 引擎已支持 `tg_set_nthreads` |
| **Vulkan 队列优先级** | 给 GPU 队列更高优先级 | ✅ `VkDeviceQueueCreateInfo.queuePriority` |
| **进程优先级/亲和性** | GPU 相关线程绑到指定核 | ✅ Windows API |
| **内存配额**（类似 PCL）| 防止 OOM，不增带宽 | ✅ 用户态可做 |
| **大页（Large Pages）** | 减少 TLB miss，提升有效带宽 | ✅ Windows 需授权 |

## 五、结论

| 你的问题 | 答案 |
|---|---|
| 能给核显划专属内存吗？ | ✅ 能（BIOS UMA Frame Buffer，本机当前 512 MB）|
| 能让 CPU 不抢吗？ | ⚠️ 能划地址范围，但**物理内存条是同一对，带宽不变** |
| 能提升核显推理速度吗？ | ❌ **不能** —— 瓶颈是 DRAM 带宽，不是"抢" |
| 那什么有意义？ | ✅ **软件层**：减少线程竞争、队列优先级、大页 |
| 最值得做的？ | ✅ **做一个启动器**（你要的那个配置面板）|
