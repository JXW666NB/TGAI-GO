## 一、先说清楚：真正的门槛是什么

```
❌ 常见误解："只要设备能做矩阵运算就能跑 TGAI"

✅ 准确的说法：
   "只要【内存装得下模型】，TGAI 就能跑。算力只决定速度，不决定能不能。"

依据（实测）：
  用【纯标量 C、无 AVX2、无 NEON、无 OpenMP、单线程】编译引擎
    → ✅ 编译通过（232,960 B，只依赖 kernel32）
    → ✅ 生成成功，20 tokens / 28.1s = 0.7 tok/s
  ⇒ 计算侧几乎无门槛；同一模型在 AVX2 8 线程上是 11.2 tok/s，差 16 倍但都对
```

### 四道真实门槛

| # | 门槛 | 说明 | V2.7 (3B) 实际需要 |
|---|---|---|---|
| ① | **内存** | 权重 + KV cache + 工作区 | 5.6 GB + ~1.8 GB ≈ **7.5 GB** |
| ② | **存储** | 能放下 `.TG` 文件 | **5.64 GB** |
| ③ | **带宽** | decode 每 token 要读一遍权重 | 实测已接近 51.2 GB/s 上限 |
| ④ | **算力** | **只影响速度** | 标量 0.7 / AVX2×8 11.2 tok/s |

### 引擎的依赖（实测 `dumpbin /dependents`）

```
libtgai_engine.dll / .so
    └── 只有系统内核库（Windows: KERNEL32.dll）
        · 静态链接 CRT，不依赖 MSVC 运行时 / glibc 版本
        · 只用 C 标准库: malloc/free/memcpy/memset
                        expf/logf/sqrtf/cosf/sinf/powf
                        fopen/fread
        · 不调 BLAS / Eigen / PyTorch / any ML 库
⇒ 理论上任何有 C99 编译器的平台都能移植
```

**SIMD 是可选加速，不是必需**（源码 `tgai_engine.c` L54-69）：

```c
#if defined(__ARM_NEON) || defined(__ARM_NEON__)
    #define TG_HAS_NEON 1
#elif defined(__AVX2__)
    #define TG_HAS_AVX2 1
#else
    #define TG_HAS_NEON 0
    #define TG_HAS_AVX2 0      /* ← 走进标量路径，仍然正确 */
#endif
```

## 三、★ 关于 GPU：一个必须诚实说明的结论

**别对外说"支持 GPU 加速"而不加限定**。本机实测：

| 配置 | tok/s | 相对 CPU |
|---|---|---|
| CPU 引擎（AVX2 8线程） | 11.20 | — |
| GPU 桥（全部算子走核显） | 5.70 | **−49.1%** |
| GPU 桥（仅大算子） | 11.00 | −1.8% |
| 输出一致性 | ✅ 三者逐字相同 | |

**为什么核显不快**（已量化）：

```
① 逐算子桥接不可行：RMSNorm 计算 0.043 µs，Vulkan dispatch 100~500 µs
   ⇒ 差 2325 倍
② decode（seq=1）时计算量太小，核显算力优势用不上
③ 核显与 CPU 【共享同一条内存总线】⇒ 抢不出额外带宽
```

**GPU 唯一有实测优势的场景**：prefill（seq≥8）
```
实测: GPU 164.1 GFLOP/s  vs  CPU 单线程 2.83 GFLOP/s  ⇒  58×
```

⇒ **正确表述**：
> "支持 CUDA / Vulkan 后端，**但当前逐算子桥接在本机核显上比 CPU 慢**；
>  GPU 的优势只在 prefill（长 prompt 首算）。纯 CPU 是当前推荐的默认路径。"

## 五、这个引擎"不挑设备"的原因（技术上）

| 设计 | 带来的好处 |
|---|---|
| **纯 C99，零依赖** | 不需要 BLAS/Eigen/PyTorch，交叉编译容易 |
| **静态链接 CRT** | 不挑系统版本（实测 DLL 只导入 kernel32） |
| **SIMD 可选** | 没有 SIMD 就标量跑，仍然正确（只是慢） |
| **多线程可选** | `TG_SINGLE_THREAD` 宏可关掉整个线程池（嵌入式/无 pthread 平台） |
| **`.TG` 单文件** | 权重 + BPE 分词器 + 元数据都在一个文件里，没有外部依赖 |
| **对话配置内嵌** | `.TG` 可自带对话模板 ⇒ 换模型不用改代码 |
| **WASM 可用**（理论） | 代码无平台专属系统调用 ⇒ 可编译到 wasm32 |

**移植到新平台需要做的**：
1. 用该平台 C 编译器编 `src/tgai_engine.c`
2. 若平台无 pthread ⇒ 加 `-DTG_SINGLE_THREAD`
3. 若有 SIMD ⇒ 加 `-mavx2` / `-mfpu=neon` 等标志（可选）
4. 完成

## 六、对外表述建议（三个版本）

### 严谨版（技术场合、文档）
> TGAI GO 是纯 C 推理引擎，只依赖 C 标准库。**能不能跑取决于内存** ——
> 设备要有足够 RAM 装下模型权重。**算力只决定速度**：
> 实测同一模型在纯标量 CPU 上 0.7 tok/s，AVX2 8 线程上 11.2 tok/s，
> 差 16 倍但结果都正确。

### 一句话版（宣传）
> **只要内存装得下，TGAI 就能跑 —— 同一份代码，从 ESP32 单片机到 GPU 服务器。**
> 实测：ESP32-S3 跑 7.8M 模型 3 tok/s，PC 跑 3B 模型 11.2 tok/s。

### 带分级版（最准确）
```
7.8M  Q4_0  3.0 MB   → ESP32-S3（16MB Flash + 8MB PSRAM）  3 tok/s ✅实测
1B    三值  212 MB   → 手机旗舰 / RK3588 / Jetson
3B    BF16  5.6 GB   → 8GB+ 内存 PC / 服务器               11.2 tok/s ✅实测
```
