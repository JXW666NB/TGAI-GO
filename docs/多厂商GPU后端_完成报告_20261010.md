## 三、我踩的 4 个坑（都记录在代码注释里）

### 坑 1：手写 Vulkan 结构体 → 进程崩溃（最严重）

```
现象: 测试程序退出码 3221226505 (0xC0000409 = STATUS_STACK_BUFFER_OVERRUN)
根因: 我按记忆手写 VkPhysicalDeviceProperties 等结构体，
      字段布局与真实 Vulkan ABI 不一致
      ⇒ 驱动按真实布局往里写 ⇒ 越界写 ⇒ 崩
修法: 下载官方 vulkan_core.h（27,715 行），绝不自造 Vulkan 类型
```

### 坑 2：`stage` 是保留字

```
VkPipelineShaderStageCreateInfo.stage 在 C++ 里是关键字冲突源
（我的自造版本改了名，但用官方头文件后就不存在这个问题）
```

### 坑 3：官方头文件的 include 层级

```
volk.h 里写的是 #include <vulkan/vk_platform.h>
vulkan_core.h 里写的是 #include <vk_video/vulkan_video_codec_h264std.h>
⇒ 目录必须是 third_party/vulkan/ + third_party/vulkan/vk_video/
  并且 -I third_party（不是 -I third_party/vulkan）
```

### 坑 4：Windows SDK 的 DXC 不带 SPIR-V 后端

```
dxc.exe -spirv ⇒ "SPIR-V CodeGen not available.
                   Please recompile with -DENABLE_SPIRV_CODEGEN=ON"
pyshaderc ⇒ 无预编译 wheel，本地编译失败
⇒ 唯一可行: 源码编译 glslang（CMake + Ninja + MSVC，约 20 MB 源码）
```

## 五、架构说明

### 内存策略（针对核显优化）

```
核显 = 统一内存（UMA）⇒ HOST_VISIBLE|DEVICE_LOCAL 是同一块物理内存
⇒ 上传/下载就是 memcpy，零 staging buffer、零拷贝
   （实测 heap 7.95 GB，is_uma=是）

独显 = 分离内存 ⇒ 当前先用 HOST_VISIBLE（能跑通），
       后续可加 staging buffer + vkCmdCopyBuffer 优化带宽
```

### 后端选择（设计，待接线）

```
TG_BACKEND=auto    依次试 cuda → vulkan → cpu
TG_BACKEND=cuda    强制 NVIDIA
TG_BACKEND=vulkan  强制（AMD/海光/摩尔线程/Intel 走这条）
TG_BACKEND=cpu     强制 CPU（永远兜底，绝不跑不起来）
```
