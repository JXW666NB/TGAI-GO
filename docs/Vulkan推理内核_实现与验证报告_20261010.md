## 二、内核设计要点

### 2.1 RMSNorm

```
y[i] = x[i] / sqrt(mean(x²) + eps) * w[i]

实现：一个工作组处理一行（一个 token）
      local_size = 256，共享内存树形归约求平方和
TGAI V2.7: eps = 1e-6, d_model = 1024
```

### 2.2 SiLU × Mul（SwiGLU）

```
o[i] = silu(g[i]) * u[i]
silu(x) = x * sigmoid(x) = x / (1 + exp(-x))

对应 TGAI MoE 专家的 w1(gate) / w3(up) 相乘
```

### 2.3 Softmax（数值稳定）

```
① 减最大值（防 exp 溢出）② exp ③ 除以和
一个工作组处理一行，共享内存归约
★ 用 ±50 的大数值测试验证了数值稳定性
```

### 2.4 BF16 矩阵乘（split-K）

详见 `BF16矩阵乘内核优化_完成报告_20261010.md`

## 三、★ 本轮踩的坑（RoPE 的竞态，已修）

```
❌ 第一版 RoPE：就地改写 qkv buffer
   读 q0/q1 → 旋转 → 写回同一位置
   问题：一个线程处理 pair i 时，另一线程可能同时读同一对 ⇒ 竞态
   ⇒ 结果不确定（时对时错）

✅ 修正：读 QKV(binding 0) → 写 QOUT(binding 4) / KVC(binding 3)
   代价：多一份 Q 输出缓冲（seq=1 时仅 4 KB，可忽略）
```

**这是"看似能跑、实则不确定"的典型** —— 如果只测一次可能碰巧过。

## 四、累计踩坑清单（Vulkan 后端全程）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 进程崩 `0xC0000409` | 手写 Vulkan 结构体做 ABI 猜测 | 用官方 `vulkan_core.h` |
| 2 | 结果全错（4080/4096）| push constant std430 对齐（12≠16 倍数）| `layout(offset=N)` + padding |
| 3 | 只有第 0 行对 | 分派维度写反（`row=ID.y` 但 N_OUT 在 X 维）| `gx=列/16, gy=行/16` |
| 4 | `atomicCompSwap` 无重载 | GLSL 450 core 没有 uint 版（ES 3.1 才有）| 改「分段输出 + CPU 规约」|
| 5 | `uint[4](...)` 语法错 | GLSL 不支持数组构造 | 用 `uvec4` 分量 |
| 6 | `const uint*` 传参错 | GLSL buffer 数组不能当指针传 | 内联进循环 |
| 7 | **RoPE 结果不确定** | **就地读写同一 buffer ⇒ 竞态** | **分离输入/输出 buffer** |
| 8 | 行分块版快 2.1× 但全错 | 设计不适合 seq 小（列方向 15/16 闲置）| 改用 split-K |
| 9 | "46 GFLOP/s" 假数据 | 分派维度错 ⇒ 只算了 1/256 工作量 | 修正维度后是 7 GFLOP/s |

**坑 9 最值得警惕** —— 错误的分派维度会给出"性能超好"的假象。

## 七、关于 TGAI ORV

已确认 **TGAI ORV 是训练框架**（有 `orv_cpu_bwd_test` 反向传播测试、
`loss` / `optim` 模块、以及 vision/video_3d/vae/dit/audio_codec 等多模态模块）。

**TGAI GO 支持训练后 ORV 确实可以退役**，而且有额外优势：
- ORV 只有 CPU（llvm-mingw + OpenMP + AVX2）
- TGAI GO 已具备 **CUDA + Vulkan（跨五厂商）** 后端
- 同一份代码推理+训练，维护成本减半

**建议保留顺序**：
1. 先完成推理主线（剩余 6~8 天）
2. 再补反向传播内核（复用现有前向内核 + 原子浮点扩展）
3. 验证通过后再退役 ORV（**不要提前删**）
