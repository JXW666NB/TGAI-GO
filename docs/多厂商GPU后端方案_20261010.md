# ★ 多厂商 GPU 后端方案（NVIDIA / AMD / 海光 / 摩尔线程）

**日期**：2026-10-10
**需求**：TGAI GO 要兼顾 CPU 和 GPU，且不只 NVIDIA —— 还要兼容 AMD、海光（Hygon DCU）、摩尔线程（Moore Threads）

---

## 一、现状盘点（实测）

| 项 | 状态 |
|---|---|
| **CUDA 后端** | ✅ **源码完整**（`cuda/tgai_cuda.cu` 43 KB），**已验证可编译** |
| **产物** | `cpu\build\libtgai_engine_gpu.dll`（130,048 B，34 个导出符号）|
| **CUDA 运行时** | ✅ 已恢复（cublasLt 451.6 MB + cublas 95.4 MB + cudart 0.5 MB）|
| **构建脚本** | ✅ 新建 `build_cuda.bat`（一条命令，用 MSVC 主机编译器）|
| **本机 GPU** | ⚠️ 只有 **AMD Radeon 核显**（无 NVIDIA）|
| **AMD / 海光 / 摩尔线程** | ❌ 无任何后端 |

### 关键发现：CUDA 版是"引擎 + CUDA 后端"打成一个 DLL

```
错误做法：nvcc 只编 tgai_cuda.cu
  ⇒ LNK2019: 无法解析 tg_config / find_weight / get_cached_weight / tg_forward

正确做法：nvcc 同时编 tgai_engine.c + tgai_cuda.cu
  ⇒ 34 个符号（tg_* 引擎 API + tg_cuda_* GPU API）全部导出 ✅

含义：GPU 版 DLL 是【自包含】的 —— Python 端只加载这一个 DLL，
      不需要额外的 CPU DLL。这为后端抽象提供了干净的基础。
```

## 二、五个候选计算栈的对比（查到的事实）

| 厂商 | 计算栈 | 代码复用 | 授权/门槛 | 备注 |
|---|---|---|---|---|
| **NVIDIA** | CUDA | **已有** | 免费 | 市占最高 |
| **AMD** | HIP / ROCm | 高（HIP 是 CUDA 的"方言"）| 免费 | Linux 主战场；Windows 支持较新 |
| **海光 DCU** | **ROCm/HIP 兼容** | **高** | 免费 | 国产，兼容 ROCm 生态 |
| **摩尔线程** | **MUSA**（类 CUDA）| **高** | 免费 | 国产，工具链 `mcc` 对标 `nvcc` |
| **全平台** | **Vulkan Compute** | 中（需重写内核）| **最广** | N/A/AMD/海光/摩尔线程/Intel **都支持** |

### ★ 核心洞察：Vulkan 是唯一能"一套代码通吃五家"的路径

```
Vulkan Compute 覆盖：
  ✅ NVIDIA      （驱动自带）
  ✅ AMD         （驱动自带，含核显）
  ✅ 海光 DCU     （有 Vulkan 驱动）
  ✅ 摩尔线程     （有 Vulkan 驱动）
  ✅ Intel       （驱动自带）
  ✅ Linux / Windows / Android 三平台
```

**代价**：Vulkan 的 LLM 推理性能通常低于厂商原生栈（约 60~80%），
因为要自己做内存管理、管线屏障、工作组调优。

## 三、推荐架构：后端插件化 + 运行时自动选择

### 3.1 分层

```
┌──────────────────────────────────────────────────────────┐
│  tgai_chat.py / tgai_server.py / tgai_tui.py  (Python)   │
└────────────────────────┬─────────────────────────────────┘
                         │ 只认 tg_* API（不变）
┌────────────────────────▼─────────────────────────────────┐
│  libtgai_engine.dll          引擎核心（纯 C，已有）        │
│    ├── tg_forward()  ──┐                                 │
│    ├── CPU 内核（AVX2/NEON，已有）                        │
│    └── 后端调度表 ◄────┼─── 新增：函数指针表               │
└────────────────────────┼─────────────────────────────────┘
                         │ 运行时 dlopen 选一个
      ┌──────────────────┼──────────────────┬──────────────┐
      ▼                  ▼                  ▼              ▼
  ┌────────┐      ┌──────────┐      ┌──────────┐   ┌──────────┐
  │ CUDA   │      │ HIP/ROCm │      │  MUSA    │   │ Vulkan   │
  │ NVIDIA │      │ AMD/海光  │      │ 摩尔线程  │   │ 通用兜底  │
  │ 已有✅  │      │ 待建     │      │ 待建     │   │ 待建⭐   │
  └────────┘      └──────────┘      └──────────┘   └──────────┘
```

### 3.2 后端接口（统一契约）

```c
/* tgai_backend.h —— 所有后端必须实现这一组函数 */
typedef struct {
    const char* name;              /* "cuda" / "hip" / "musa" / "vulkan" / "cpu" */
    int  (*init)(void);            /* 探测硬件；返回 1=可用, 0=不可用 */
    void (*shutdown)(void);
    void* (*load)(TGModel* m);     /* 上传权重到显存 */
    void  (*free)(void* h);
    const float* (*forward)(void* h, const int32_t* ids, int n,
                            TGKVCache* kv, int pos);
    void  (*set_extend)(void* h, int extend_ctx);
    int   (*mem_info)(size_t* free_b, size_t* total_b);
} TGBackend;

/* 注册表：按优先级探测 */
extern const TGBackend TG_BACKEND_CUDA;
extern const TGBackend TG_BACKEND_HIP;
extern const TGBackend TG_BACKEND_MUSA;
extern const TGBackend TG_BACKEND_VULKAN;
extern const TGBackend TG_BACKEND_CPU;      /* 永远可用 */
```

### 3.3 运行时选择逻辑

```c
/* 优先级：环境变量指定 > 自动探测 > CPU */
TG_BACKEND=auto        /* 默认：依次试 cuda → hip → musa → vulkan → cpu */
TG_BACKEND=cuda        /* 强制 */
TG_BACKEND=vulkan      /* 强制（国产卡走这条）*/
TG_BACKEND=cpu         /* 强制 CPU */
```

**探测顺序的理由**：
1. 厂商原生栈性能最好 ⇒ 先试
2. Vulkan 最后（通用兜底，性能次之但一定能跑）
3. CPU 永远兜底（保证"绝不会跑不起来"）

**遗留**：`cuda/build_cuda_win.ps1` 的 `param()` 块无法解析（PowerShell 报
`InvalidLeftHandSide`），且它要求 clang-cl。**建议废弃它，统一用 `build_cuda.bat`。**

### 阶段 2：后端抽象层（**不改变任何现有行为**）

| 步骤 | 说明 | 风险 |
|---|---|---|
| 2.1 | 新增 `src/tgai_backend.h`（接口定义）| 无（只是头文件）|
| 2.2 | CPU 内核包成 `TG_BACKEND_CPU` | 低 |
| 2.3 | 现有 CUDA 代码包成 `TG_BACKEND_CUDA` | 低 |
| 2.4 | 引擎加载时按 `TG_BACKEND` 选后端 | 低（默认 auto，行为不变）|
| 2.5 | 验证：不设环境变量时与现在**逐位相同** | 关键回归 |

### 阶段 3：Vulkan 后端（**覆盖面最大的投入**）

**为什么优先 Vulkan 而不是先做 HIP**：
```
做 HIP    ⇒ 只多支持 AMD + 海光     （+2 家）
做 MUSA   ⇒ 只多支持 摩尔线程        （+1 家）
做 Vulkan ⇒ 同时支持 AMD + 海光 + 摩尔线程 + Intel + NVIDIA  （+5 家）
```

| 步骤 | 说明 |
|---|---|
| 3.1 | 选依赖：**Vulkan-Headers**（头文件，无运行时依赖）+ 动态加载 `vulkan-1.dll` |
| 3.2 | 实现基础设施：实例/设备/队列/命令缓冲/内存分配 |
| 3.3 | 移植 3 个核心内核：**矩阵乘（BF16）**、**RMSNorm**、**RoPE + Attention** |
| 3.4 | MoE 专家按需上传（GPU 显存放不下的走 CPU）|
| 3.5 | 数值对照：与 CPU 后端逐层比（复用 `tools/compare_layers.py` 思路）|

**工作量估计**：3.2~3.4 是主体，约 3~5 天（取决于调优深度）。

### 阶段 4：原生栈补齐（可选，按需）

| 后端 | 触发条件 | 工作量 |
|---|---|---|
| HIP | 有 AMD/海光 机器要榨性能 | HIP 是 CUDA 方言，移植约 1 天 |
| MUSA | 有摩尔线程机器要榨性能 | 同上，`mcc` 对标 `nvcc` |

## 六、给用户的话

### 关于 AMD（本机现有的卡）

本机是 **AMD Radeon 核显**（无 NVIDIA）。两条路：
1. **Vulkan** —— 核显也支持，能立刻验证（阶段 3）
2. **ROCm/HIP on Windows** —— AMD 的 Windows 支持较新，装起来较重

**建议走 Vulkan**：一次投入覆盖五家厂商，且本机就能自测。

### 关于国产卡

| 卡 | 现状 | 建议 |
|---|---|---|
| **海光 DCU** | 兼容 ROCm/HIP | 阶段 4 做 HIP 后端即可覆盖 |
| **摩尔线程** | MUSA 类 CUDA | 阶段 4 做 MUSA 后端 |
| **两家都支持的通用路径** | **Vulkan** | **阶段 3 一次覆盖** |

**如果暂时没有国产卡实物**：先做 Vulkan（本机 AMD 核显可验证），
等有卡了再补 HIP/MUSA 原生后端榨性能。
