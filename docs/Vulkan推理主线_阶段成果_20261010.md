## 三、后端抽象层（新增，关键基础设施）

### 设计

```c
struct TGBackend {
    const char* name;
    uint32_t    caps;                    // 能力位（MM/NORM/ROPE/ATTN/MOE/KV/...）
    int  (*init)(void);                  // 1=可用
    void (*shutdown)(void);
    void* (*alloc)(size_t);              // 设备内存
    int   (*upload)(void*, const void*, size_t);
    int   (*download)(void*, const void*, size_t);
    void* (*map)(void*);                 // 零拷贝指针
    int  (*rmsnorm)(...);  (*silu_mul)(...);  (*softmax)(...);
    int  (*rope)(...);     (*mm_bf16)(...);   (*attention)(...);  (*moe_router)(...);
    void* priv;
};
```

```

             GPU=Y  UMA=Y  mem=7.95 GB

    ★ 跨后端数值对比 (CPU vs Vulkan RMSNorm):
       err_max = 1.667e-07   不符 = 0/4096   ✅ 一致
```

## 四、GPU 侧 KV cache（新增）

### 为什么需要

```
引擎原有 KV cache 在主机内存
⇒ GPU 注意力内核每次都要 upload ⇒ 白费带宽（核显的瓶颈正是带宽）
GPU 侧 cache 让数据一直待在设备内存，注意力内核直接读，零传输
```

### 实测

```
容量 128 位置，总计 1024 KB，主机可映射 ✅（零拷贝）
逐 token 追加 32 次 ✅
★ GPU 注意力直接读 KV cache（零 upload）:
   CPU vs GPU err_max=7.781e-05  不符=0/1024  ✅
重置 ✅    容量边界: 128 次后正确拒绝 ✅
```

## 五、★ 本阶段踩的坑（累计 12 个）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 崩 `0xC0000409` | 手写 Vulkan 结构体做 ABI 猜测 | 用官方 `vulkan_core.h` |
| 2 | 结果全错（4080/4096）| push constant std430 对齐（12≠16 倍数）| `layout(offset=N)` + padding |
| 3 | 只有第 0 行对 | 分派维度写反（`row=ID.y` 但 N_OUT 在 X 维）| `gx=列/16, gy=行/16` |
| 4 | `atomicCompSwap` 无重载 | GLSL 450 core 没有 uint 版（ES 3.1 才有）| 改「分段输出 + CPU 规约」|
| 5 | `uint[4](...)` 语法错 | GLSL 不支持数组构造 | 用 `uvec4` 分量 |
| 6 | `const uint*` 传参错 | GLSL buffer 数组不能当指针传 | 内联进循环 |
| 7 | RoPE 结果不确定 | **就地读写同一 buffer ⇒ 竞态** | 分离输入/输出 buffer |
| 8 | 行分块快 2.1× 但全错 | 设计不适合 seq 小（列方向 15/16 闲置）| 改用 split-K |
| 9 | "46 GFLOP/s" 假数据 | 分派维度错 ⇒ 只算 1/256 工作量 | 修正后是 7 GFLOP/s |
| **10** | **Attention 全错（1024/1024）** | **点积+树形归约放循环里，每次 barrier，时序微妙** | **改「一个线程算一个完整 score」，消除归约** |
| 11 | Attention 共享内存爆（32 KB）| 想把全部 score 放共享内存 | online softmax 分块（TILE=128）|
| 12 | `uint pid` 只读变量冲突 | PowerShell 保留变量 | 改名 |

### 坑 10 是最有价值的一个

```
❌ 第一版：score[j] = reduce(q·K[j])   ← 在 j 循环里做树形归约 + barrier
   ⇒ 全错，GPU 输出像是"所有 score 相等"

✅ 第二版：一个线程算一个完整的 score[j]（串行 d 循环，无归约、无 barrier）
   ⇒ err_max=4.488e-05，完全正确
```

**教训：共享内存归约 + barrier 的组合极易出错；能用"每线程独立任务"就用它。**
